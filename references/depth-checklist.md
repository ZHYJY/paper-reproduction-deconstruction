# 默认深度与反简略检查清单

本文件是 `SKILL.md` 的配套判据。每次调用 `paper-reproduction-deconstruction` 时，默认输出必须满足“默认深度标准”，交付前必须通过“反简略检查”。

## 默认深度标准（强制）

以下 6 项为最小交付深度，不因用户未说“详细”而省略：

1. **提示工程/输入设计拆解**
   - 还原完整提示模板（system / user / few-shot / chain-of-thought）。
   - 说明输出格式、解析规则、温度/采样参数、角色设定、不确定性出口。
   - 给出不同模型/条件间的提示差异。
   - 用逐样本评分分布说明模型行为（如正向偏见、UNKNOWN 比例）。
   - 指出提示中可能导致结果偏差的设计选择。

2. **经济机制与理论解释**
   - 将主结果映射到理论预测：符号、方向、异质性、动态衰减。
   - 对附录模型给出简化叙述，明确假设和命题。
   - 讨论竞争解释，并说明作者如何排除或控制它们。
   - 解释“这个系数/排序/衰减为什么在经济上有意义”。

3. **全表全图映射**
   - Table/Figure 1–N 与生成脚本、输入文件、关键 CSV 字段、聚合口径一一对应。
   - 未映射项显式标为 `unmapped`。
   - 代码中存在但正文未解释的默认行为标为 `implementation detail`。

4. **代码精读**
   - 至少精读 3 个核心脚本/函数。
   - 用短代码片段说明关键实现（路径 + 行号/函数名）。
   - 指出论文未写明但影响结果的默认行为。

5. **逐元素数值核对**
   - 至少核对 1 张主表 + 1 张边界/消融表。
   - 给出论文值、复现值、单位/指标方向、绝对差、相对差、容差、状态和诊断。
   - 使用 `scripts/compare_numbers.py` 生成可审计的对照表。

6. **局限的因果链**
   - 区分“材料缺失”“运行阻塞”“实现差异”“统计不确定性”“外部有效性”。
   - 每项给出证据、影响和可执行的下一步。

如果任一项因材料缺失无法完成，报告状态卡必须降级为 `partial` 并说明缺失项；不得以“作者已经写了”为由跳过。

## 反简略检查（交付前强制自检）

命中以下任意一条，必须返回补充，不得交付：

- [ ] 报告仅有“作者发现 A、B、C”式摘要，没有逐段论证链。
- [ ] 没有独立的“提示工程/输入设计拆解”或“经济机制/理论解释”章节。
- [ ] Table/Figure 映射只有文件名列，没有具体到脚本、字段、聚合口径和运行 ID。
- [ ] 代码映射只列了目录，没有短代码片段和实现细节说明。
- [ ] 数值核对只有“基本一致”，没有逐项 abs_diff/rel_diff/tolerance 表。
- [ ] 局限只有一句“数据不可得”，没有区分缺失类型、影响和下一步。
- [ ] 思维导图少于 6 个一级分支或节点只是章节标题复述。
- [ ] slides 没有至少 1 页公式逐行解释和 1 页结果对照表。

补充完成后，在报告状态卡标注 `deep-dive-passed`。
